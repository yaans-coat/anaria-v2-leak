### Features

- **Floating dock:** icon dock on the left (home, games, chatroom, privacy, dmca, account, settings) with hover magnification and tooltips, plus an omnibox toolbar with back/forward/reload and a loading progress bar.
- **Home:** neon wordmark, rotating one-liners, search bar with quick links (site logos), official github/discord links and a recent-traffic list that only appears when history is on.
- **Games page:** the whole `/games` library served by `/api/games`, filterable, each game embedded inline in a player.
- **Chatroom:** broadcast hub on `/chat/` (WebSocket, in-memory). Requires a local username — no accounts, no persistence.
- **Setup & help:** skippable welcome panel on first load, plus a floating help bubble with a quickstart and how-to-use guide.
- **Settings page:** preferences, appearance, cloaking, advanced and credits — validated, persisted, applied instantly. The cloak action lives in the cloaking tab.
- **30 themes:** grape (official default), nord, mint, cappuccino, latte, dracula, gruvbox, catppuccin and more, with animated toast notifications on every swap.
- **Cloaking:** disguised tab title/favicon, about:blank wipe and a configurable panic key.
- **Traffic history:** every navigation with status, type, timing and relative age, stored locally only and toggleable.
- **Backdrop snow:** drifting snow behind the UI, tinted from the active theme and paused with animations off.
- **Legal pages:** privacy policy and dmca pages written for a proxy that neither hosts nor sells anything.
- **Transport switching:** Pick libcurl, epoxy or bare at runtime, or point at another wisp server. Status only surfaces when a protocol actually changes.
- **Quiet service worker:** Silence log, info and debug inside the worker. Warnings and errors stay.

```
public/js/notify.js   animated toast notifications
public/js/engine.js   the ONLY file that talks to the proxy engine
public/js/url.js      address-bar input -> URL
public/styles.css     every style, animation and ui-style variant
```

`engine.js` implements a small interface (`init`, `createSession`, `setTransport`).
Feature modules use that interface. Changing transports also changes server mounts,
dependencies, service-worker files, and transport setup.

It also pings the service worker every 15 seconds. That is not optional. Browsers
terminate an idle service worker after about thirty seconds, and Scramjet keeps its
routing table in the worker's module scope, so a cold worker cannot route and the
first navigation after a quiet period lands on this server's 404 instead. Removing
the interval reintroduces that bug.

## Requirements

- **HTTPS in production.** Service workers do not run on plain HTTP
  (localhost is exempt).
- **Cross-origin isolation.** The server sets `Cross-Origin-Opener-Policy`
  and `Cross-Origin-Embedder-Policy`. The engine does not need these to
  run, but it re-sends them onto proxied responses, which is what lets a
  proxied site use `SharedArrayBuffer`. Drop them and any site that needs
  it breaks from inside its own code. Keep them.
- **WebSockets.** The Wisp tunnel is a long-lived WebSocket, so serverless
  hosts will not work. Use a VPS, Render, Fly, Railway, or similar.

### The service worker keepalive

`engine.ts` pings the service worker every 15 seconds. That is a
workaround for an upstream bug, not something Scramjet asks for: browsers
terminate idle service workers, Scramjet's worker loses the frame prefixes
it was routing, and every navigation after that lands on this server's 404
until you reload. Posting a message resets the idle timer.

Delete it once upstream fixes the revive handshake.
